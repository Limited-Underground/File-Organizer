# Disposable feasibility and benchmark plan

Status: prepared, not executed. No benchmark harness, software installation, real-data scan, USB action, service registration or installer run is authorized by this document. Production code remains blocked pending architecture review and explicit implementation authorization. Small fixture/harness implementation and every expensive/device/admin test need a separately scoped task.

## Reproducibility and safety

Each future run uses an explicit task-owned `artifacts/bench/<run-id>/` workspace on the approved local checkout drive, outside indexed real-data roots. The harness must reject drive roots, existing directories, paths outside the approved disposable workspace, reparse-point ancestry and insufficient free space before generating fixtures. No discovery scan of the user's profile is permitted. Persist a manifest of generated relative names, sizes, seeded content recipe, expected SHA-256 and fixture root identity before mutation. Hardware tests additionally require named sacrificial media/VM and owner approval. Do not use system USN reset/resize or global fault injection on the host.

Record OS/build, filesystem, CPU/RAM, storage model/free space, runtime/package/native SQLite versions, source commit, configuration, random seed, dataset hash, case/link capabilities and background load. Defaults are proposed comparison conditions: Windows 11, 4 logical cores, 16 GiB RAM and local SSD with at least 20 GiB free. Results from other environments must identify the difference. Use release builds without debugger; report cold and warm cache separately rather than claiming OS cache was cleared. For stable workloads use one warmup and five measured runs, median/p95 plus min/max. Report enumeration errors, not just speed. All budgets below are proposed review thresholds, not measured claims.

Emit machine-readable measurements and a short human receipt into the run directory. Retain harness version, fixture manifest, expected/actual digests, failure state and logs; redact real paths from any public evidence. Cleanup is an explicit final action after evidence capture: resolve/check the exact owned boundary and delete only manifest-owned disposable files with no retention hold. Never delete recovery evidence after a failure to make a run look clean. Do not run independent disk-heavy cases concurrently.

## Planned cases

| Case | Reproducible fixture and procedure | Measures / proposed acceptance |
|---|---|---|
| B01 — million-record SQLite | Generate 1,000,000 metadata rows with seed 104729: 100 roots, 10,000 directories, skewed sizes, repeated names and 1% hard-link entries; do not create one million physical files. Load in bounded transactions, run ANALYZE, then 100 seeded queries each for paged children, name prefix, size sort, volume/offline filters and size duplicate candidates. | Correct row/object counts and stable paging with no skips/duplicates; on baseline warm UI queries p95 <=250 ms for 200-row page, aggregate query <=2 s, worker peak RSS <=1 GiB; record load time, DB/WAL size, query plans. Budgets become binding only after owner accepts baseline. |
| B02 — initial/incremental scan | Separate physical fixture: 20,000 files/1 GiB deterministic data, nested and Unicode/long names, 100 empty directories. Scan; then manifest-driven 1,000 creates, 1,000 renames, 500 edits and 500 removals. Reconcile and compare against fixture oracle. | Exact entry/object/content metadata coverage, no false deletion; report files/s, MiB/s, CPU, allocation/RSS, latency and error count. Target incremental work <25% of full-scan time when valid feed coverage exists; fall back correctness wins over speed. |
| B03 — USN interruption/gap | Unit-test captured synthetic supported USN records with rename halves, reordered/coalesced events, journal-ID change, cursor below first valid USN and unsupported record version. Later approved disposable NTFS VHD/VM test: stop worker, make seeded mutations, restart; simulate unavailable journal through adapter. Real rollover only on approved sacrificial volume, never host journal. | Each valid cursor replays exactly once logically; every gap marks stale coverage and reconciles to oracle. Denied journal access uses non-elevated fallback. No false Current status while gaps remain. |
| B04 — watcher overflow/reconcile | Inject overflow/error through test adapter; burst manifest mutations on physical fixture; stop/restart worker during burst and repeat without watcher. | All missed changes repaired by reconciliation, cancellation does not mark scan complete, denied/offline subtrees never tombstoned. Measure catch-up latency and bounded notification queue. |
| B05 — staged duplicates | 5,000 generated files/2 GiB: exact duplicates, same-size differing middle content, matching sampled ranges with different unsampled bytes, empty files, hard links and intentional-backup paths. Compare full oracle with size/sample/full stages. Change a file during hash and invalidate cached observations. | Zero false exact-duplicate groups or reclaimable hard-link bytes; ambiguous/changed reads rejected. Record bytes read by stage, CPU, throughput, cache hit/invalidation and peak RSS; staging should read less than full hashing of all candidates on this fixture. |
| B06 — pause/resume/cancel | Transfer generated files including 0-byte, small, 256 MiB and >4 GiB cases (large case separate expensive approval). Pause before/after each checkpoint; restart both processes, resume; cancel at each phase. | Final hashes match; unfinished move items retain source, completed moves remain completed, and every item outcome is reported. Durable offset never exceeds flushed bytes; request retry never duplicates an operation. Pause acknowledgment <=2 s on local baseline except explicitly reported blocking OS calls; report durable versus displayed progress. |
| B07 — crash/corruption matrix | Process-only kill fault injection at intent commit, partial creation, chunk flush, checkpoint commit, verification, CommitPending, promotion, source-delete intent, source deletion and terminal journal commit. Corrupt/truncate only generated partial/destination, mutate source and substitute a same-name different object. | Recovery converges to valid completion or actionable preserved evidence; no source deletion without verified intended destination and unchanged source. Mismatch never silently succeeds; existing replacement retained until safe commit. Run each deterministic boundary at least three times. Power-loss durability requires separate approved VM/device test. |
| B08 — USB disconnect | On separately approved sacrificial USB containing only fixture data, disconnect during copy, flush, verify and cross-volume move deletion boundary. Reconnect with changed drive letter; also present a different volume at original letter. | Operation waits safely, identifies original volume and resumes only after validation; wrong-volume/changed-source actions refused. Preserve both copies on uncertainty. Report hardware, filesystem, disconnect point and independently verified hashes. Not replaceable by host mocks for physical acceptance. |
| B09 — permissions/locked files | Within disposable VM or approved fixture ACL scope, deny read/list/write/delete individually; open generated files with incompatible sharing; release lock during bounded retry. Add inaccessible subtree. | No automatic elevation/ownership change, typed actionable failures, bounded retries, accessible items continue by explicit policy, inaccessible subtree shown incomplete with no false deletion. Capture before/after fixture ACLs and restore only owned fixture policy. |
| B10 — links/path races | Approved generated hard links, junction, symlink to another fixture subtree and a link pointing to a sentinel outside scan root (sentinel is also task-owned). Include cycles, case-sensitive names, source-to-descendant destination and parent replacement while committing. Symlink privilege enabling prohibited; skip with capability reason if unavailable. | No default traversal; sentinel unchanged, hard-link accounting correct, unsupported links reported. Mutation detects stale parent/entry identity and stops before affecting replacement. Long path and alternate-stream preservation limits are explicit. |
| B11 — SQLite interruption | Crash writer at transaction boundaries during inventory/journal updates, inject disk-full in a disposable quota/VHD environment, exercise busy reader, WAL checkpoint and controlled damaged database copies. Use online backup and run integrity/foreign-key checks after restart and restored copy. | Last committed journal transitions retained, incomplete transactions absent, recovery status honest, original damaged set preserved. Never recover by dropping operation tables. Record backup/restore duration and WAL growth. Disk-full simulation never fills host drive. |
| B12 — worker/IPC lifecycle | Submit with idempotency key, sever pipe, restart desktop/worker; replay request, use stale protocol, unauthorized user and oversized messages in disposable test account/VM. Shutdown with queued/running jobs; restart while profile lock held. | Exactly one operation/worker per profile, state snapshots recover missed events, incompatible/unauthorized messages cause no I/O, shutdown leaves recoverable jobs. Proposed idle shutdown <=5 s; blocked I/O reported rather than falsely completed. |
| B13 — upgrade/rollback/uninstall | Disposable Windows 11 VM: install version A, seed inventory/nonterminal jobs/quarantine manifest, upgrade B with schema migration, interrupt at installer and migration phases, test failed migration and older binary startup; uninstall/reinstall. Signing/installer development separately authorized. | User data and journals retained, schema backup verified, incompatible binary refused, worker quiesced. Binary rollback never opens incompatible schema; restore requires explicit recovery and no loss of later operations. Uninstall default retains data and never touches fixture user-content/quarantine roots. Capture VM baseline and package hashes. |

## Evidence gates

Record each case as Not run, Pass, Fail, Blocked or Not applicable with a concrete reason. Do not substitute a performance number for correctness, a synthetic adapter pass for physical USB acceptance, an integrity check for recoverability, or installer build success for upgrade acceptance. A one-million-row database is not a one-million-file scan result. Initial readiness review needs approved protocols and scoped next tasks; V1 release later needs accepted correctness, performance, security, installation and physical-media results for supported scenarios.

Benchmarks target the mechanisms in [architecture](ARCHITECTURE.md). Baseline/reference limits must be revised through reviewed evidence if hardware or product requirements change, rather than silently weakening a failed test. Record the approved expensive-test time/disk budget before execution and stop on budget breach with partial receipts preserved.
