| Area | Recommendation | Alternatives, tradeoffs and validation |
|---|---|---|
| Runtime and language | Keep .NET 10 LTS and C# 14. The local tool inventory observed SDKs 10.0.303 and 8.0.426; use the .NET 10 SDK for this product. | Pin the selected SDK when implementation starts, maintain servicing patches and audit packages. .NET 10 has support through November 2028. No SDK installation is authorized by this foundation. [Microsoft support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core), [C# 14](https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/csharp-14) |
| Desktop UI | Prefer Avalonia and MVVM for Windows now and Linux later. | WPF is mature for Windows integration but Windows-only. Avalonia requires validation of accessible keyboard navigation, virtualized large listings, drag/drop and shell integration. Current Avalonia docs list Windows 11 24H2 x64/ARM64 as Tier 1 and 22H2 as Tier 2; propose 24H2 x64 as the initial validated baseline, subject to owner acceptance. [Avalonia platform matrix](https://docs.avaloniaui.net/docs/supported-platforms), [WPF overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/) |
| SQLite access | Start with Microsoft.Data.Sqlite, parameterized SQL, explicit migrations and a bounded single-writer queue. | EF Core adds mapping/migration convenience but more behavior to tune for bulk ingestion; defer unless a measured benefit appears. Microsoft.Data.Sqlite async methods execute synchronously, so database work belongs off the UI thread. Use prepared commands and bounded transaction batches. [Provider overview](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/), [Async limitations](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/async) |
| Database concurrency and durability | Local disk WAL, explicit foreign keys and FULL synchronization for durable operation commits. | WAL supports readers alongside one writer, not multiple writers or network filesystem placement. Long readers can prevent checkpoint progress. NORMAL can improve throughput but may lose recent commits after power failure; do not silently apply it to operation evidence. Measure batching, WAL bounds and checkpoint pauses. [SQLite WAL](https://www.sqlite.org/wal.html), [PRAGMA reference](https://www.sqlite.org/pragma.html) |
| Database backups | Use SQLite's backup API and validate the backup before migration. | A live main database file alone is insufficient in WAL mode. Microsoft.Data.Sqlite BackupDatabase blocks concurrent writers; schedule and measure that pause. Inventory backup is distinct from backing up indexed user files. [Online backup](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/backup) |
| Windows filesystem access | Use System.IO for ordinary enumeration and streams; isolate handle-based Win32 calls in the Windows adapter. | Use GetFileInformationByHandleEx/FileIdInfo for identity, deliberate reparse-point handling and volume capability checks. Native calls increase ownership and error-handling obligations; avoid exposing handles to UI/domain code. [FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info), [Reparse points](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-points) |
| File identity | Record volume instance plus volume serial and 128-bit file ID where supported; store paths separately. | Windows documents the serial/file-ID pair for identifying a file on one computer. It is not a permanent global identity across volume cloning, reformatting or identity reuse. Hard-link paths refer to one underlying object; unsupported filesystems need explicit weaker identity semantics. [Identity API](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info) |
| Change detection | Baseline scan + FileSystemWatcher hints + periodic reconciliation; optional NTFS USN acceleration. | Watcher buffers can overflow and operations can emit duplicate events. Coalesce into dirty scopes, keep handlers short and reconcile after overflow/disconnect. USN improves catch-up but is volume/filesystem/access dependent; ordinary users must retain a working fallback. [Watcher contract](https://learn.microsoft.com/en-us/dotnet/api/system.io.filesystemwatcher?view=net-10.0), [Change journals](https://learn.microsoft.com/en-us/windows/win32/fileio/change-journals) |
| USN continuation | Persist journal ID and cursor atomically with the inventory updates they cover. | Compare current journal identity and available bounds before replay. Changed ID, truncation, discontinuity or unsupported records require reconciliation. Never create, resize or delete a journal automatically. The journal is an indexing aid, not a source-content backup. [USN journal fields](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-usn_journal_data_v0), [USN administration effects](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/fsutil-usn) |
| Duplicate detection | Size grouping, sampled partial hash, then full SHA-256; stream content with bounded concurrency. | Partial hashes only filter candidates. Full hashes require fresh identity/version checks; intentional backup sets and hard links must remain distinguishable. Before an approved destructive action, revalidate the actual handles/content. CPU and storage contention, especially HDD seeks, determine concurrency. [SHA256 stream API](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.sha256.hashdata?view=net-10.0) |
| Background execution | One per-user worker owning the shared engine; no Windows Service by default. | An in-process worker is simpler but ends with the UI. A separate per-user worker can finish accepted jobs after window closure. A Windows Service enables logged-out operation but adds privilege, credential and lifecycle complexity; require a new accepted requirement before choosing it. [Worker/service model](https://learn.microsoft.com/en-us/dotnet/core/extensions/windows-service) |
| IPC | Versioned local named pipes, same-user restrictions, bounded messages and operation IDs. | Direct calls are sufficient for an in-process prototype; keep application commands transport-neutral. Reject arbitrary filesystem commands outside validated plans. .NET named pipes use Unix-domain sockets on Linux; the documented Unix CurrentUserOnly socket-permission tightening starts with .NET 11, so future .NET 10 Linux support needs a private endpoint directory and explicit permission tests. [Named pipes](https://learn.microsoft.com/en-us/dotnet/standard/io/how-to-use-named-pipes-for-network-interprocess-communication) |
| Installation | Prefer MSI direction; evaluate current WiX terms before selecting an exact tool version. | MSI gives explicit storage and enterprise upgrade control but requires careful authoring. MSIX offers managed deployment/state separation; virtualization and uninstall cleanup must be proven compatible with journal/inventory retention. MSI rollback does not automatically undo application database migrations. [MSI rollback](https://learn.microsoft.com/en-us/windows/win32/msi/rollback-installation), [MSIX runtime behavior](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes) |
| Future Linux | Preserve platform adapter and storage-location boundaries; keep portable engines in ordinary .NET libraries. | Linux file identity, case sensitivity, mount instances, permissions and notification loss require distinct implementations and contract tests. Avalonia Linux dependencies and supported distribution tiers vary; do not claim Linux readiness from Windows tests. [Avalonia Linux matrix](https://docs.avaloniaui.net/docs/supported-platforms) |

## Dependency and distribution terms

The product license remains Apache 2.0, with free official distribution and personal/commercial use. Dependency notices remain independent obligations.

- Avalonia core is [MIT licensed](https://github.com/AvaloniaUI/Avalonia/blob/main/licence.md). Commercial IDE tools, support and optional products have separate terms; do not silently add them as build prerequisites.
- SQLite deliverable code is [public domain](https://www.sqlite.org/copyright.html). Managed/native providers and bundled libraries must still be checked separately.
- Current WiX source is under its [repository license](https://github.com/wixtoolset/wix/blob/main/LICENSE.TXT); current official binary releases also carry an [Open Source Maintenance Fee agreement](https://github.com/wixtoolset/wix/blob/main/OSMFEULA.txt). Its fee applies to qualifying revenue-generating use with annual gross revenue at least US$10,000. Owner review of the selected version and terms is required before adopting those binaries. This does not change File Organizer's Apache license.
- No application dependency versions have been selected or restored. Before the first dependency PR, inspect exact package SPDX/license expression, native/transitive components, notices, maintenance support and known advisories; retain required notices and a dependency inventory. Build-only tools and shipped components need separate treatment. Do not infer redistribution permission solely from a NuGet package name.
