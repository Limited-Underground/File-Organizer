# Security reporting

There is no released or supported executable yet. Security concerns about this foundation are welcome.

After repository setup, use GitHub **Security > Advisories > Report a vulnerability** for private reports. Private vulnerability reporting must be enabled and read back before this route is advertised as operational. Until enabled, a private reporting contact is an owner setup gate; do not file exploit details, credentials or personal file paths in public issues.

Include affected version/commit, impact, minimal synthetic reproduction and proposed mitigation if known. Do not attach real inventories, user files, credentials or identifying logs. Maintainers should acknowledge within seven calendar days and provide a status update within thirty; these are proposed response targets pending maintainer assignment. Coordinate disclosure after remediation; no automated publication deadline is imposed.
